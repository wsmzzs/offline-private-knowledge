# 能力边界与验收方法

这个项目的目标是帮助用户根据私有资料问答。它通过检索、证据筛选、提示约束和引用校验降低无依据回答，但这些措施不能证明每一句模型回答都忠实于资料。

## 当前边界

- 支持 TXT、Markdown、DOCX、带文字的 PDF 和 XLSX。扫描图片 PDF、图片、旧版 DOC/XLS 不支持；没有 OCR。复杂表格、跨页排版和图表可能丢失关联，建议提供结构清楚的文字说明。
- 文件大小、解压大小、页数、文件数和片段数有上限。超过限制时应查看项目状态并拆分资料；具体默认限制在 `appsettings.json`。
- 每次问题独立，只检索当前项目。没有跨项目查询、多轮指代消解或自动代办操作。
- 检索到相关片段不代表一定包含答案。语义阈值、片段长度和证据预算可能造成漏检；模型也可能误拒答或补充原文没有的内容。小模型尤其需要用实际问题核对。
- 引用校验确认引用属于本次提供的资料片段，不能自动证明答案中的每个事实都由引用支持。重要结论应点击原文核对。
- 本地模型需要预先下载。客户端不会把私有资料发给在线模型；模型下载和在线模型目录是需要网络的独立功能。配置的 Ollama 地址应指向可信的本机或内网部署。
- 当前企业部署使用实例共享密钥，没有个人账号、项目级权限、操作审计中心和生产容量保证。
- 当前交付和验收目标为 Windows x64。客户端使用 Avalonia，但未完成 macOS/Linux 运行包与平台验收。

## 如何验收自己的知识库

先准备一组有明确原文答案的问题，再准备一组资料没有答案的问题。记录“正确答案、原文件、原段落”，不要只看模型回答是否流畅。

| 类别 | 虚构样例问题 | 应观察什么 |
| --- | --- | --- |
| 明确事实 | 连接成功后怎样显示温度曲线？ | 回答启用通道、开始采集和勾选曲线，并引用操作资料 |
| 换一种说法 | 能连上设备却看不到曲线，漏了哪一步？ | 同样找到显示曲线的操作步骤 |
| 项目隔离 | 在点检工具问如何提交点检记录 | 只引用点检记录工具的资料 |
| 没有依据 | 这台设备的合格温度是多少？ | 说明资料未规定，不编造温度值 |
| 自动更新 | 修改虚构操作说明，等待修订号增加再问 | 使用新资料，旧回答保持原样 |

自动测试默认使用隔离资料和模拟模型协议，验证解析、索引、接口、取消、权限与界面状态。它们不衡量真实模型的中文能力。可选的真实模型验收工程需要本机已有 Ollama 和对应模型，运行方式见 [发布与验证](RELEASING.md)。

不要把单次演示通过写成“准确率 100%”或“已满足企业生产要求”。更可信的记录应注明模型版本、资料集、问题数量、硬件、等待时间，以及检索漏答、模型误答和无依据问题的拒答情况。
